# Branches in `dev-main`

Every change in [`dev-main`](https://github.com/erwinvaneijk/whatsapp-mcp/tree/dev-main), one branch each, with what it does. Most are upstream pull requests from [lharries/whatsapp-mcp](https://github.com/lharries/whatsapp-mcp); the rest are changes made in this fork. How the branches work is in the [README](../README.md#about-this-fork-and-its-branches).

Since version 0.9 the MCP server is a Rust program, `whatsapp-mcp serve`, and the Python server is gone. Entries about the Python server are kept for the record and marked as such; what they fixed, the Rust server does too (the [parity harness](../parity/README.md) checks it). The Go bridge is still in use until 1.0, when the Rust bridge (`whatsapp-mcp bridge`) replaces it.

Bridge and connection:

- `fix/405-whatsmeow-bump` — upstream PR [#381](https://github.com/lharries/whatsapp-mcp/pull/381): updates whatsmeow to fix the `Client outdated (405)` connect error. Requires Go 1.26 or newer.
- `fix/media-403` — upstream PR [#361](https://github.com/lharries/whatsapp-mcp/pull/361): fixes the 403 error on `/api/download` for media.
- `fix/media-same-name` — upstream PR [#370](https://github.com/lharries/whatsapp-mcp/pull/370): media with the same filename in a chat (such as photos sent together) each get their own file instead of overwriting each other.
- `fix/whatsmeow-1006` — upstream PR [#392](https://github.com/lharries/whatsapp-mcp/pull/392): a newer whatsmeow, for `websocket 1006` disconnects while connecting.
- `fix/media-cdn-auth` — upstream PR [#367](https://github.com/lharries/whatsapp-mcp/pull/367): tests that media downloads keep the CDN signature. The fix itself was already in `fix/media-403`.

Security:

- `fix/api-hardening` — upstream PR [#387](https://github.com/lharries/whatsapp-mcp/pull/387): the bridge API listens on `127.0.0.1` only, requires a shared token, only sends files from one folder, and keeps downloads inside `store/`. **Changes setup:** see [Bridge token and media folder](../README.md#bridge-token-and-media-folder).
- `fix/store-permissions` — upstream PR [#389](https://github.com/lharries/whatsapp-mcp/pull/389): `store/` and its databases and media are readable by your user only.
- `feat/read-only-mode` — upstream PR [#388](https://github.com/lharries/whatsapp-mcp/pull/388): optional [read-only mode](../README.md#read-only-mode) that hides the send tools.
- `docs/security-policy` — fork change: [SECURITY.md](../SECURITY.md) explains how to report a security problem privately, through GitHub's private vulnerability reporting.

Fixes and speed:

- `fix/logs-to-stderr` — upstream PR [#372](https://github.com/lharries/whatsapp-mcp/pull/372): the MCP server logs to stderr, so log lines no longer corrupt the MCP connection. *(Python server; the Rust server does the same.)*
- `fix/last-message-join` — upstream PR [#283](https://github.com/lharries/whatsapp-mcp/pull/283): chat lists no longer duplicate or drop chats.
- `fix/list-chats-no-last-message` — upstream PR [#380](https://github.com/lharries/whatsapp-mcp/pull/380): `list_chats` and `get_chat` work with `include_last_message=False`.
- `fix/contact-chats-limits-timeouts` — upstream PR [#373](https://github.com/lharries/whatsapp-mcp/pull/373): no duplicate rows in `get_contact_chats`, negative limits are rejected, and calls to the bridge time out.
- `fix/document-mime` — upstream PR [#390](https://github.com/lharries/whatsapp-mcp/pull/390): documents are sent with their real file type and name instead of as unnamed `.bin` files.
- `fix/document-mime-type` — upstream PR [#328](https://github.com/lharries/whatsapp-mcp/pull/328): the same fix as #390; merged for its history only.
- `fix/voice-message-cleanup` — upstream PR [#369](https://github.com/lharries/whatsapp-mcp/pull/369): `send_audio_message` deletes the converted `.ogg` file after sending.
- `feat/fts5-search` — upstream PR [#281](https://github.com/lharries/whatsapp-mcp/pull/281): fast full-text search in `list_messages`. Needs the bridge built with `-tags sqlite_fts5`; without it, search uses the old slow scan. A search matches whole words or the start of a word, not text in the middle of a word.
- `feat/mcp-2x` — upstream PR [#378](https://github.com/lharries/whatsapp-mcp/pull/378): the MCP server uses mcp 2.x, so MCP clients on the 2.x protocol connect at once instead of waiting for a timeout. Needs Python 3.11 or newer. *(Python server; replaced by the Rust server in 0.9.)*
- `fix/mcp2-tool-output-types` — fork fix: with mcp 2.x every read tool failed ("Error executing tool"), because the tools declared a different return type than they returned. Fixed, with a test that calls every tool through the MCP server. *(Python server; replaced by the Rust server in 0.9.)*
- `ci/github-actions` — upstream PR [#150](https://github.com/lharries/whatsapp-mcp/pull/150): GitHub Actions builds and tests the bridge (with and without full-text search) and runs the Python tests on every push.
- `ci/python-ruff` — fork change: [Ruff](https://docs.astral.sh/ruff/) formats and lints the Python code, and CI fails when either finds something. Before committing, run `uv run ruff format && uv run ruff check --fix` in `whatsapp-mcp-server`. *(Python server, removed in 0.9.)*
- `test/parity-harness` — fork change, phase 0 of the [Rust rewrite plan](rust-1.0/plan.md): [`parity/`](../parity/README.md) runs every MCP tool against invented test data and a fake bridge, and CI compares the results with recorded golden files. [docs/rust-1.0/interface.md](rust-1.0/interface.md) describes everything 1.0 must keep.
- `spike/whatsapp-rust` — fork change, phase 1 of the [Rust rewrite plan](rust-1.0/plan.md): a small test program in [`spike/whatsapp-rust/`](https://github.com/erwinvaneijk/whatsapp-mcp/tree/e29387f7ca8106c89bb2fba0aff694f6c47472dd/spike/whatsapp-rust) that checks whether the [whatsapp-rust](https://github.com/oxidezap/whatsapp-rust) library can do everything the bridge does. The checklist and results are in [docs/rust-1.0/phase1.md](rust-1.0/phase1.md). Not part of the build or CI; removed once the Rust bridge replaced it, and kept in the history.
- `feat/rust-workspace` — fork change, phase 2 of the [Rust rewrite plan](rust-1.0/plan.md): the Cargo workspace in [`crates/`](../crates/README.md), with CI that formats, lints, tests and builds it on Linux, macOS and Windows and checks its dependencies with `cargo deny`. No features yet; the Go bridge and Python server are still what you run.
- `feat/rust-config` — fork change, phase 3 of the [Rust rewrite plan](rust-1.0/plan.md): the Rust config crate reads `config.yaml` and the environment variables with the same rules as today. The cases in [`parity/config-cases.json`](../parity/config-cases.json) run against the Go, Python and Rust code alike.
- `feat/rust-mcp-skeleton` — fork change, phase 4 step 1 of the [Rust rewrite plan](rust-1.0/plan.md): `whatsapp-mcp serve` publishes the same server name, instructions and tool definitions as the Python server, hiding the send tools in read-only mode. The parity harness can now test it (`run.py --server rust`). The tools themselves follow in the next steps.
- `feat/rust-read-tools` — fork change, phase 4 step 2 of the [Rust rewrite plan](rust-1.0/plan.md): the Rust server's eight read tools give the same results as the Python server in every harness profile, with clearer error messages for bad input.
- `feat/rust-send-tools` — fork change, phase 4 step 3 of the [Rust rewrite plan](rust-1.0/plan.md): the Rust server's send tools (`send_message`, `send_file`, `send_audio_message`, `react_to_message`, `download_media`) work through the Go bridge. The Rust server now passes the whole parity harness; bridge errors give the bridge's reason.
- `feat/release-0.9` — fork change, phase 4 step 4 of the [Rust rewrite plan](rust-1.0/plan.md): version 0.9. The Rust MCP server replaces the Python one, which is removed; the Go bridge stays. The installation steps and an upgrade section are updated, and the parity harness now records and checks the Rust server only.
- `feat/rust-bridge-plan` — fork change, phase 5 step 1 of the [Rust rewrite plan](rust-1.0/plan.md) ([steps](rust-1.0/phase5.md)): the Rust store writes `messages.db` exactly as the Go bridge does (same schema text, migrations, full-text index, time format), with two new tables for contact names that the MCP server reads when they exist.
- `feat/rust-bridge-api` — fork change, phase 5 step 2 of the [Rust rewrite plan](rust-1.0/plan.md): the Rust bridge's local API (`/api/send`, `/api/react`, `/api/download`), with the Go bridge's token check, error texts, status codes and send allowlist, tested without a WhatsApp connection.
- `feat/rust-bridge-receive` — fork change, phase 5 step 3 of the [Rust rewrite plan](rust-1.0/plan.md): `whatsapp-mcp bridge` links with a QR code or pairing code, keeps its session in `store/session.db`, and stores incoming messages, history sync, chat and group names, contacts and the LID map in `messages.db`. Tested live with the test account.
- `feat/rust-bridge-send` — fork change, phase 5 step 4 of the [Rust rewrite plan](rust-1.0/plan.md): the Rust bridge sends text, replies, mentions, files and voice notes, reacts, and downloads media into `store/<chat>/`, asking the sender's phone again for expired media. Sent messages are stored in the chat that already exists for the contact.
- `feat/rust-bridge-security` — fork change, phase 5 step 5 of the [Rust rewrite plan](rust-1.0/plan.md): `serve` and `bridge` log the settings and paths they run with on start; the WhatsApp session and downloads are readable by your user only; every bridge log line was reviewed, with control characters removed from all error texts.
- `fix/gitignore-binary` — upstream PR [#349](https://github.com/lharries/whatsapp-mcp/pull/349): git ignores the compiled bridge program.
- `fix/sqlite-indexes` — upstream PR [#279](https://github.com/lharries/whatsapp-mcp/pull/279): database indexes for faster message and chat queries.
- `fix/sqlite-wal` — upstream PR [#393](https://github.com/lharries/whatsapp-mcp/pull/393): faster history sync and WAL mode for the databases.

Contacts and messages:

- `fix/contact-names-lid` — upstream PR [#375](https://github.com/lharries/whatsapp-mcp/pull/375): chats and senders show the saved contact name instead of a bare number, also for chats on WhatsApp's newer LID IDs. Searching by phone number finds LID chats too. Names come from the bridge's `whatsapp.db`; a newly saved contact can take up to 10 seconds to show up.
- `fix/media-captions` — upstream PR [#350](https://github.com/lharries/whatsapp-mcp/pull/350): captions on images, videos and documents are stored as the message text instead of being dropped, also for messages from history sync. Applies to newly received or re-synced messages.
- `feat/store-non-text-messages` — upstream PR [#345](https://github.com/lharries/whatsapp-mcp/pull/345): reactions, polls, poll votes, locations, contact cards, stickers, edits and deletes are stored as short bracketed text (such as `[reaction: ❤️]` or `[edited] new text`) instead of being dropped. Applies to newly received messages.
- `feat/reply-to-message` — upstream PR [#277](https://github.com/lharries/whatsapp-mcp/pull/277): `send_message` can reply to a specific message with `reply_to_message_id`. For group chats, also pass `reply_to_sender_jid` (the original sender).
- `feat/send-file-caption` — upstream PR [#200](https://github.com/lharries/whatsapp-mcp/pull/200): `send_file` takes an optional `caption`, shown with the image, video or document.
- `feat/send-mentions` — upstream PR [#321](https://github.com/lharries/whatsapp-mcp/pull/321): `send_message` takes `mentions`, a list of phone numbers or JIDs to @mention. Also put `@<number>` in the text, or WhatsApp does not highlight it. Works together with replies.
- `feat/send-reactions` — upstream PR [#148](https://github.com/lharries/whatsapp-mcp/pull/148): new `react_to_message` tool to react with an emoji, or remove your reaction with an empty one. The message must be in the bridge's database. Hidden in read-only mode.
- `feat/quoted-message-id` — upstream PR [#325](https://github.com/lharries/whatsapp-mcp/pull/325): replies are stored with the ID of the message they quote and shown as `(reply to <id>)`. Every message now shows its ID, to use with replies and reactions. Applies to newly received or re-synced messages.
- `feat/store-sent-messages` — upstream PR [#383](https://github.com/lharries/whatsapp-mcp/pull/383): messages and reactions sent through the bridge are stored, so they show up in `list_messages` and can be replied or reacted to. They go into the existing chat, whether that is stored under the phone number or the LID.
- `feat/tool-annotations` — upstream PR [#142](https://github.com/lharries/whatsapp-mcp/pull/142): every tool tells MCP clients whether it only reads, or sends messages that cannot be undone (so the client can ask first).
- `feat/media-retry-pair-code` — upstream PR [#273](https://github.com/lharries/whatsapp-mcp/pull/273): media that has expired on WhatsApp's servers is requested again from the sender's phone (which must be online), and the bridge can link with a code instead of a QR code (`WHATSAPP_PAIR_PHONE`).
- `log-content-opt-in` — fork PR [#1](https://github.com/erwinvaneijk/whatsapp-mcp/pull/1) by BadPirate, with fixes in `fix/log-privacy`: message content stays out of the bridge's logs unless `WHATSAPP_LOG_CONTENT=1` is set, and media keys are never logged. See [Logs](../README.md#logs).
- `feat/mark-untrusted-content` — fork change: message text from others is marked as data and the model is told never to follow instructions in it, to limit prompt injection (upstream issue [#247](https://github.com/lharries/whatsapp-mcp/issues/247)). See [Messages from others are marked as data](../README.md#messages-from-others-are-marked-as-data).
- `feat/send-allowlist` — fork change: `send_allowlist` (or `WHATSAPP_SEND_ALLOWLIST`) limits which chats the bridge sends to, and all settings can come from a [configuration file](../README.md#configuration) (upstream issue [#218](https://github.com/lharries/whatsapp-mcp/issues/218); send-only alternative to upstream PR [#319](https://github.com/lharries/whatsapp-mcp/pull/319)). See [Limit who the bridge sends to](../README.md#limit-who-the-bridge-sends-to).
- `fix/timezones` — fork fix for upstream issue [#146](https://github.com/lharries/whatsapp-mcp/issues/146): `list_messages` filters on the actual moment, so `after`/`before` give the same result whether written in local time, UTC or another zone (they were off by one or two hours), and message times are shown with their UTC offset. A time without a zone is local time on the computer running the MCP server.
